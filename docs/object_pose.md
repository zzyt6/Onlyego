# 物体位姿（object_pose）：手拿着的物体每一帧在哪、朝哪

代码：`src\object_pose\`。命令：`object_pose baseline`（V2D 的跟丢处理）、`object_pose run`（我们的）、`object_pose view`。

前提：`object_model run`（网格、SAM2 mask、参考帧位姿）和 `video_depth run`（深度、相机位姿）。
网格形状和尺度在 `object_model` 定死，这里每帧只求 6 个数（旋转 + 平移）。

## 1. 基线：V2D 的跟踪，从我们拟合的位姿出发（`object_pose baseline`）

V2D（`src\HOI\pipelines\run_ego_wilor.py` 第 8 步）的物体跟踪：

1. **FoundationPose 跟踪**（`HOI.foundation_pose.foundation_pose_tracker`）：参考帧上 `register`（从零找位姿，10 轮），
   然后往后到结尾、往前到第 0 帧，每帧用上一帧位姿做初值，RGB + 深度精修 5 轮（物体 mask 外的深度置 0）。
   网格投影和 SAM2 mask 的 IoU < 0.3 就当跟丢了，这一帧重新注册。
2. **EKF + RTS 平滑**（`HOI.foundation_pose.run_ekf_smoothing`）：随机游走模型，前向卡尔曼 + 反向平滑；深度方向（Z）
   测量噪声 0.04 是横向 0.01 的 4 倍（单目深度 Z 最不准）；每帧测量噪声 × 1/IoU。
3. （可选，V2D 默认关）高斯泼溅联合精修手、物体、相机。

这里的基线 = 1 + 2 不改算法，输入换成我们的：`object_model` 的网格和参考帧（demo01：第 23 帧）+ Codex 生成的贴图
（`mesh_textured.glb`，`four_stage_view generate-texture`）、MegaSaM 深度、SAM2 mask。
唯一的改动是起点：参考帧不让 FoundationPose 自己注册，直接用 `object_model` 拟合好的位姿（轮廓 IoU 0.98）。
这个位姿只靠几何（融合点云 + 轮廓），不受贴图好坏影响；FoundationPose 自己注册要靠贴图分辨朝向，
用 SAM3D 自带贴图时把对称的盒子转了 180°。跟丢后的重新注册仍是 FoundationPose 自己的。

`fp_track.py` 在 WSL 的 `hoi-fp` 环境里跑（TensorRT 后端），184 帧约 70–90 秒。

### 评分（`evaluate.py`）

| 指标 | 含义 |
|---|---|
| 整体 IoU | 网格轮廓 vs SAM2 盒子 mask（V2D 的重新注册和 EKF 看的就是这个）。手指挡在盒子前面时 mask 缺一块，位姿完全对也到不了 1 |
| **可见部分 IoU** | 两边都去掉手的像素（SAM2 手 mask）再比：手拿着时公平的分数 |
| 网格 − 深度 | 可见的盒子像素上，网格深度减 MegaSaM 深度的中位数（+ = 网格在深度后面） |
| 静止段漂移 | 手碰到之前盒子没动：每帧算出的"物体→世界"和 `object_model` 拟合的位姿差多少（mm / 度） |
| 抖动 | 世界坐标平移的二阶差分（mm/帧²） |

### 结果文件（`runs\object_pose\<视频>\baseline\`）

`poses_raw\`（FoundationPose 每帧位姿，V2D 的 Transform3d JSON，物体→相机）、`poses_ekf\`（平滑后）、
`track.json`（每帧 IoU、是否重新注册）；`metrics_<raw|ekf>.json`（逐帧指标）、`summary.json`；
`overlay_<raw|ekf>.mp4`（网格画在原视频上，绿线 = 盒子 mask，紫线 = 手 mask，逐帧分数）。
`object_pose view <视频>` 在 Viser 里看。

| | 静止段（0–23）可见 IoU / 漂移 / 转角 | 手拿着（24–183）可见 IoU 中位数 / p10 | < 0.9 的帧 | 抖动 |
|---|---|---|---|---|
| 原始 | 0.947 / 2.8 mm / 1.8° | 0.704 / 0.574 | 117 / 160 | 7.7 mm |
| + EKF | 0.948 / 2.7 mm / 1.8° | 0.671 / 0.572 | 131 / 160 | 1.1 mm |

按时间段（原始，可见 IoU 中位数）：24–55 手刚拿起 0.94；59–99 双手换手、盒子翻转 0.76；第 99 帧盒子
几乎出画，触发重新注册（174 帧又一次）；104–149 盒子半出画 0.61；150–183 放回桌面 0.58。

看到的问题：
- **静止段稳**：离拟合位姿约 3 mm / 2°。（对照：用 Codex 贴图时 FoundationPose 自己注册也能摆对，结果几乎相同；
  用 SAM3D 贴图时自己注册转反 180°。以后只保留从拟合位姿出发。）
- **第 99 帧以后跟偏**：盒子放下时朝上的是另一面（实物上有波浪和太阳图案，参考图 03 拍到了），Codex 贴图把这一面
  画成了纯浅青色，FoundationPose 用颜色对不上，网格被拉到旁边。要改的是贴图（让 Codex 用上所有参考图），不是跟踪。
- **EKF 只去抖不纠偏**：抖动 7 → 1 mm，但坏的段更坏。
- 换手、翻转的那段（59–99）仍是难点。

## 2. 我们的跟丢处理（`object_pose run`，结果在 `ours\`）

基线的问题出在跟丢以后：第 99 帧盒子快出画，整体 IoU < 0.3 触发重新注册，FoundationPose 只看到半个盒子，
选了一个转错约 90° 的朝向；之后 IoU 一直在 0.55–0.6，高于 0.3，错的位姿被带了 70 帧，网格还沉到桌面下 2–13 cm。
FoundationPose 逐帧跟踪只修小误差，转不回来。`fp_track.py --recovery ours` 只改"什么时候、怎么重新注册"，
FoundationPose 本身不动：

1. **跟丢判断用可见部分 IoU**（网格和 SAM2 mask 都去掉手的像素）：连续 2 帧 < 0.8，或一帧 < 0.5。
   手挡住不再像跟丢，转错 90° 的 0.6 也能抓到。（直接把整体 IoU 门槛提到 0.8 不行：手拿着时几乎每帧都触发注册，
   每次几十秒。）
2. **看不全时不注册**：盒子 mask 碰到画面边缘，或突然小于最近面积中位数的一半（被切掉、被挡住），继续跟踪，
   等完整出现再注册。
3. **注册时自己挑候选**：FoundationPose 注册时精修好的约 250 个候选全部拿来，先按 SAM2 轮廓筛（可见 IoU 不低于
   最高值 − 0.03，排除转错 90° 之类），再在剩下的里取 FoundationPose 打分最高的（它比的是带贴图的渲染和照片，
   分得出正面背面、头尾 180°；这些轮廓一样，IoU 差 0.01 只是噪声，不能拿来决定）。新位姿的可见 IoU 比当前高
   0.02 才换；每 5 帧最多试一次。
   （试过"IoU + 打分名次 + 离上一个可靠位姿的转角"加权，放下后选成了背面朝上：轮廓相同，IoU 噪声和转角先验
   压过了贴图。）

`track.json` 每帧另记 `iou_visible`、`reliable`（yes / edge / partial / no mask）和每次注册选中的候选。

可见 IoU 中位数（括号里是最低）：

手拿着（24–183）整体：可见 IoU 中位数 0.704 → 0.929，< 0.9 的帧 117 → 48 / 160，网格 − 深度 +6.3 → +0.1 mm，
抖动 7.7 → 1.8 mm。重新注册 5 次（第 73、82、89、94、110 帧）。放下段渲染贴图和照片逐帧比，正反、头尾都对；
基线这段转错 90° 并沉到桌面下。

还剩的问题：
- **第 99–109 帧**：盒子被画面边缘切掉，按规则不注册，跟踪完全跑偏（IoU ≈ 0），第 110 帧盒子完整后才找回。
  这些帧 `reliable = edge`，以后可以用前后可靠帧插值，或用手的位姿约束。
- 换手那段（56–99）盒子侧对镜头，侧面没图案，正反只能靠轮廓，还没逐帧核对。
- EKF 平滑仍然只去抖：p10 从 0.72 降到 0.43（把 99–109 的跑偏抹进了邻近帧）。

## 3. 下一步

- 被画面切掉的帧：前后可靠帧之间插值，或用手约束；
- 每帧在 FoundationPose 结果上再精修：轮廓为主且只比没被手挡的像素，深度只当截断的弱约束；
- 世界坐标里平滑：静止段（接触前、放下后）位姿固定；
- 用手：握住期间"手→物体"相对位姿基本不变（WiLoR / MANO）。
