# 物体位姿（object_pose）：手拿着的物体每一帧在哪、朝哪

代码：`src\object_pose\`。命令：`object_pose run <视频>`、`object_pose view <视频>`。

前提：`object_model run`（网格、SAM2 mask、参考帧位姿）、`four_stage_view generate-texture`（Codex 贴图，
`mesh_textured.glb`）和 `video_depth run`（深度、相机位姿）。
网格形状和尺度在 `object_model` 定死，这里每帧只求 6 个数（旋转 + 平移）。

## 做法

`fp_track.py` 在 WSL 的 `hoi-fp` 环境里跑 FoundationPose（`HOI.foundation_pose.foundation_pose_tracker`，TensorRT 后端）：

- **起点**：`object_model` 的参考帧（demo01：第 23 帧），位姿直接用 `object_model` 拟合好的（轮廓 IoU 0.98）。
  这个位姿只靠几何（融合点云 + 轮廓），不让 FoundationPose 自己注册。
- **逐帧跟踪**：往后到结尾、往前到第 0 帧，每帧用上一帧位姿做初值，RGB + 深度精修 5 轮（物体 mask 外的深度置 0）。
  网格带 Codex 贴图。
- **跟丢处理**，FoundationPose 本身不动，只管"什么时候、怎么重新注册"：
  1. **跟丢判断用可见部分 IoU**（网格和 SAM2 mask 都去掉手的像素）：连续 2 帧 < 0.8，或一帧 < 0.5。
     手挡住不会被当成跟丢，转错 90° 的 0.6 也能抓到。
  2. **看不全时不注册**：盒子 mask 碰到画面边缘，或突然小于最近面积中位数的一半（被切掉、被挡住），继续跟踪，
     等完整出现再注册。
  3. **注册时自己挑候选**：FoundationPose 注册时精修好的约 250 个候选全部拿来，先按 SAM2 轮廓筛（可见 IoU 不低于
     最高值 − 0.03，排除转错 90° 之类），再在剩下的里取 FoundationPose 打分最高的。它的打分比的是带贴图的渲染和照片，
     分得出正面背面、头尾 180°；这些情况轮廓一样，IoU 差 0.01 只是噪声，不能拿来决定。新位姿的可见 IoU 比当前高
     0.02 才换；每 5 帧最多试一次。

184 帧跟踪约 150 秒。

### 为什么这样定（demo01 上试过的）

- V2D 原来的规则（整体 IoU < 0.3 就重新注册，直接取 FoundationPose 打分第一的候选）：第 99 帧盒子快出画时注册，
  只看到半个盒子，转错约 90°；之后 IoU 一直在 0.55–0.6，高于 0.3，错的位姿被带了 70 帧，网格沉到桌面下 2–13 cm。
  手拿着那段可见 IoU 中位数只有 0.70（我们的是 0.93）。
- 把整体 IoU 门槛直接提到 0.8：手拿着时几乎每帧都触发注册，每次几十秒，跑不动。
- 挑候选用"IoU + 打分名次 + 离上一个可靠位姿的转角"加权：放下后选成了背面朝上，因为 IoU 的噪声和转角先验压过了贴图。
- V2D 的 EKF + RTS 平滑：只去抖不纠偏，还会把跑偏的帧抹到邻近帧（p10 0.72 → 0.43），已去掉。
- 让 FoundationPose 自己注册起点：用 SAM3D 自带贴图时把对称的盒子转反 180°；用 Codex 贴图时结果和拟合位姿几乎一样。
  所以起点只用拟合位姿。

## 评分（`evaluate.py`）

| 指标 | 含义 |
|---|---|
| 整体 IoU | 网格轮廓 vs SAM2 盒子 mask。手指挡在盒子前面时 mask 缺一块，位姿完全对也到不了 1 |
| **可见部分 IoU** | 两边都去掉手的像素（SAM2 手 mask）再比：手拿着时公平的分数 |
| 网格 − 深度 | 可见的盒子像素上，网格深度减 MegaSaM 深度的中位数（+ = 网格在深度后面） |
| 静止段漂移 | 手碰到之前盒子没动：每帧算出的"物体→世界"和 `object_model` 拟合的位姿差多少（mm / 度） |
| 抖动 | 世界坐标平移的二阶差分（mm/帧²） |

## 结果文件（`runs\object_pose\<视频>\`）

| 文件 | 内容 |
|---|---|
| `poses\` | 每帧位姿（Transform3d JSON：四元数 wxyz + 平移，物体→相机） |
| `track.json` | 每帧整体 IoU、可见 IoU、`reliable`（yes / edge / partial / no mask）、是否重新注册、选中的候选 |
| `metrics.json`、`summary.json` | 逐帧指标、汇总 |
| `overlay.mp4` | 网格画在原视频上，绿线 = 盒子 mask，紫线 = 手 mask，逐帧分数 |

`object_pose view <视频>` 在 Viser 里看网格随位姿移动，和每帧点云、相机一起。

## demo01（2026-11-11，Codex 贴图 texture-01）

可见 IoU 中位数：

| 时间段 | 可见 IoU |
|---|---|
| 0–23 静止 | 0.947（离拟合位姿 2.8 mm / 1.8°） |
| 24–55 刚拿起 | 0.937 |
| 56–99 换手、翻转 | 0.794 |
| 100–149 半出画、放下前 | 0.934（第 99–109 帧 ≈ 0） |
| 150–183 放回桌上 | 0.929 |

手拿着（24–183）整体：可见 IoU 中位数 0.929、p10 0.724，< 0.9 的帧 48 / 160，网格 − 深度 +0.1 mm，抖动 1.8 mm。
重新注册 5 次（第 73、82、89、94、110 帧）。放下段渲染贴图和照片逐帧比，正反、头尾都对。

还剩的问题：
- **第 99–109 帧**：盒子被画面边缘切掉，按规则不注册，跟踪完全跑偏（IoU ≈ 0），第 110 帧盒子完整后才找回。
  这些帧 `reliable = edge`。
- 换手那段（56–99）盒子侧对镜头，侧面没图案，正反只能靠轮廓，还没逐帧核对。
